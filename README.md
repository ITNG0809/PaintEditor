# PaintEditor（コスチュームエディター ＋ アニメーション）

ブラウザだけで動く、Scratch風のコスチュームエディターです。
**ビルド不要の静的サイト**なので、このフォルダの中身をそのままGitHub Pagesなどに置けば動きます。

## フォルダ構成

ZIPを展開すると、中身がそのまま直下に並びます（親フォルダなし）。`index.html` を開けばすぐ動き、そのままGitHub Pagesなどに置けます。

```
index.html               画面のHTML（骨組み）。下のCSS/JSを読み込む
icon.svg                 タブのアイコン
style.css                すべてのスタイル（音エディター部分 → 本体部分の順）
scratch-compat.js        Scratch/TurboWarp互換（Canvas版レンダラー ＋ sb3/sprite3のプログラム変換）
sound-core.js            音の処理の核（WAV/ADPCM読込・再生・音ブロック・Workerの起動）
sound-effects.js         音の加工（フェード・エコー・リバーブ・フィルターなど。PaintAudio.fx）
costume-editor.js        コスチュームエディター本体（描画・図形・保存/読込・ブール演算・オフセット など）
bitmap-layers.js         ビットマップのレイヤー
animation.js             アニメーション機能（シーン・ブロックエディタ・実行エンジン・拡張機能）
sound-editor.js          音エディターの画面
mp4-audio.js             MP4/MOVの音声トラックだけを必要な範囲だけ読み出す部品（動画音声抽出用）
video-audio-extract.js   動画音声抽出の画面と処理（音エディターの「動画から音声を抽出」から開く）
sound-dsp-worker.js      音の速度・音程変更（Web Worker。index.htmlからは読み込まず、sound-core.jsが起動する）
sound-dsp-engines.js     速度・音程変更の処理本体（WSOLA／位相ボコーダー／SoundTouch。Workerが読み込む）
soundtouch.js            外部ライブラリ SoundTouchJS（LGPL。LICENSE-soundtouch・NOTICE-soundtouch.md付き。消さないでください）
docs-*.md / SOUND-QUALITY.md   機能ごとの仕様メモ・音質の調査結果
```
すべてのファイルは同じ階層にあり、`import "./..."` や `new URL("./...", document.baseURI)` の相対パスで読み込みます。移動するときは全部を同じフォルダに置いてください。

## 画像効果（渦巻き・魚眼など）の仕組み

`animation.js` の「画像効果」部分は、TurboWarp/Scratchと同じく **GPU（WebGLのシェーダー）** で計算します。

- 色・魚眼・渦巻き・ピクセル化・モザイク・明るさを、1ピクセルずつ並列にGPUで計算（計算式はScratchと同じ）
- 効果をかける前の絵はオブジェクトごとに使い回し、コスチューム・大きさ・解像度が変わった時だけ作り直す（実行中のみ）
- GPUに送るテクスチャも、絵が変わった時だけ送り直す
- 同じ効果の2回目以降（スタンプの連打・動かない効果）は計算結果も使い回す
- 大きいスプライト（大きさ400など）は、1回に計算するピクセル数に上限を設け、解像度を少し下げて軽くする
- WebGLが使えない／途中で失敗した時は、従来のCPU計算へ自動で切り替わる（見た目は同じ）
- 確認: `tests/（このZIPには含まれません）image-effects.mjs`（GPUとCPUの出力が一致するか・大きさ/コスチューム変更で絵が更新されるか）
- 確認: `tests/（このZIPには含まれません）screen-effects.mjs`（巨大拡大でも滲まないか・8000%・回転/画面端/画面外・GPUとCPUの一致）

## 実行エンジン（速さの仕組み）

`animation.js` の実行エンジンは、TurboWarp/Scratchと同じ考え方で動きます（詳しくは `docs-engine.md`）。

- **フレームの進め方**: 画面を動かさないループ（計算・リスト・変数など）は、1フレームの中で何千回でも回る。
  見えているオブジェクトを動かす・ペン・「待つ」などは、1周ごとに画面を更新する（Scratchと同じ）
- **コンパイル**: スクリプトをJavaScriptに変換して実行。変換できないもの（拡張機能のブロックを含むもの）は自動で従来の方式に戻る
- **当たり判定**: 実行中はコスチュームの透明度を配列にして使い回す（「触れた」「端に触れた」「クリック」）
- 不具合の切り分け: ブラウザのコンソールで `SCN.H.engine.compile = false` とすると、コンパイルを使わずに動く

## 読み込み順（変更時の注意）

`index.html` は次の順に読み込みます。**順番を入れ替えると動かなくなります。**

1. `scratch-compat.js` ・ `sound-core.js` ・ `sound-effects.js` … 部品を先に用意する（`sound-effects.js` は `sound-core.js` の後）
2. `paper.js`（CDN）
3. `costume-editor.js` … 本体
4. `animation.js` … 読み込んだ瞬間に `createPaintRenderer`（1）と `PaintAudio`（1）を使う
5. `sound-editor.js` … 本体の `SCN` `SPS` などに接続するので最後
6. `mp4-audio.js` → `video-audio-extract.js` … 音エディターの後（`PaintAudio` と `PaintSoundEditor.addPcm` を使う）

`sound-core.js` と `sound-editor.js` を1ファイルにしないのはこのためです（4を挟んで前後に分かれるため）。

## 動かし方

**手元で確認する**（`index.html` をダブルクリックで開くのは不可。音の加工に使うWorkerがブロックされます）

```sh
python3 -m http.server 8000
# → ブラウザで http://localhost:8000/ を開く
```

**GitHub Pagesで公開する**
1. このフォルダの中身をリポジトリのルートに置いてpush
2. リポジトリの Settings → Pages → Branch を `main` / `(root)` にして Save
3. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開く

パスはすべて相対パスなので、`/<リポジトリ名>/` のようなサブパスでも動きます。

## 知っておくこと

- **保存データはブラウザごと・URLごと**（localStorage）。公開URLが変わると以前の自動保存は引き継がれないので、

## ビットマップレイヤー(bitmap-layers.js)

ビットマップのコスチュームで、必要なときだけ複数レイヤーを使えます(PE独自機能。Scratch/TurboWarpにレイヤーは持ち込みません)。

- 使い方: 「パネル」を開き、ビットマップのコスチュームで「レイヤーを使う」(または＋)。今の絵が1枚目のレイヤーになります。
- 操作: 追加 / 複製 / 削除 / 名前変更(行のダブルクリックも可) / 上下移動(行のドラッグも可) / 表示・非表示 / ロック / 不透明度 / 結合(下と結合・表示中を結合・通常の画像に戻す) / 選択範囲を新規レイヤーへ分離
- 既存の描画ツールはそのまま選択中レイヤーに効きます(`c.bc` を選択中レイヤーのcanvasに向ける方式)。
- 保存(.costume): コスチュームに `ly:{ver,a,L:[{id,n,v,lk,o,u}]}` を追加(下→上の順)。従来の `bm`(統合PNG)も残すので、古い版でも統合画像として開けます。
- PNG / SB3 / SVG(画像埋め込み) / サムネイル: 表示中のレイヤーを不透明度つきで1枚に統合して出力します。
- 上限: 1コスチューム最大30枚、全レイヤー合計8000万画素(960×720なら30枚、2400×1800なら18枚)。


## 追加したScratchブロック(拡張機能を除く、Scratch 3の標準ブロックをすべて揃えました)

- 動き: 回転方法を[自由に回転/左右のみ/回転しない]にする(描画・当たり判定・保存・Scratch取り込みに反映)
- 見た目: 背景を[ ]にする / 背景を[ ]にして待つ / 次の背景にする / 背景の[番号/名前]
- イベント: 背景が[ ]に切り替わったとき(ステージのコスチューム変更でも起動)
- 音: [音程/左右にパン]の効果を変える・にする / 音の効果をなくす(音程±360・左右±100、再生中の音にも反映)
- 調べる: 音量(マイク) ※マイクが使えないときは -1。「音量(マイク)が[ ]より大きいとき」も使えます


## TurboWarp「伸縮」ブロックとURL読み込みの改善
- 見た目に追加: `伸縮を 横[X]% 縦[Y]% にする` / `伸縮を 横[X] 縦[Y] ずつ変える` / `横の伸縮` / `縦の伸縮`
  (オブジェクトの `stx` / `sty`。描画・当たり判定・クリック判定・クローンに反映。保存はせず、実行のたびに100%から)
- 拡張機能のURL読み込み: 取得時の余計なヘッダーをやめ(CORS事前確認の失敗を避ける)、`stretch` / `lab/text` のような
  公式ギャラリー名、`?extension=URL`、GitHubのページURL、http→httpsを自動で整形。GitHubはjsDelivrにも自動で切替。
  それでも取得できない時だけ、確認のうえ中継サービス(corsproxy.io)経由で再挑戦。HTMLページを取り込んだ場合は理由を表示。


## Scratch(.sb3 / .sprite3)書き出しにアニメーションのプログラムを含める
- 「ファイル」→ 書き出しで、アニメーションに置いたブロックもScratchのブロックに変換して入れます(`scratch-compat.js` の `ScratchProgramExport`)。
  - シーンが複数あるときは「プログラムを書き出すか・現在のシーンだけ/すべてのシーン」を聞きます。
  - 同じスプライトを使うオブジェクトが複数あるときは、1つ目は元の名前、2つ目以降は「名前2」「名前3」…(名前が数字で終わるときは「スプライト1 2」)の複製スプライトにプログラムを入れます。
  - 位置・大きさ・向き・表示・コスチューム・変数・リスト・メッセージ・定義ブロックも書き出します。
  - `.sprite3` は選択中のスプライトの最初のオブジェクトのプログラムを入れます(共有変数はスプライトの変数にします)。
- 拡張機能: ペン・音楽・伸縮・読み込み済みのカスタム拡張を `extensions` / `extensionURLs` に入れます。
  伸縮は公式の `https://extensions.turbowarp.org/stretch.js`(`stretch_setStretchX` など)、
  URLから読み込んだ公式ギャラリーの拡張はそのURL、ファイル/テキストから読み込んだ拡張は `data:` URLでコードごと入れます(TurboWarpで確認画面が出ます)。
- 取り込み側にも、伸縮ブロック(`stretch_*`)の変換を追加しました(横・縦を別々に設定するブロックも追加)。
- 変換できない・Scratchにないブロックは省くか中身なしで書き出し、書き出し後に一覧を表示します。


## ブロックのバックパック・コピー&ペースト・スプライトへの複製(アニメーション)
- **バックパック**: ブロック編集画面の下の帯。ブロック(または「このブロックと下のブロック」)を帯へドラッグ、または右クリック/長押しメニューの「バックパックに入れる」で保存。
  取り出すときは、帯の中のブロックを作業エリアへドラッグします。「×」で削除。
  端末のlocalStorage(`ced_bp`)に保存され、再読み込みしても残ります(最大100個。使っている定義ブロックの本体・変数名も一緒に保存)。
  必要な拡張機能が未読込のブロックは「使えないブロック」と表示され、拡張機能を読み込むと使えます。
- **コピー&ペースト**: ブロックをクリックで選び、Ctrl+C / Ctrl+V(右クリックや長押しの「コピー」「貼り付け」、帯の「貼り付け」ボタンでも可)。
  コピーは端末に保存(`ced_bclip`)するので、別のスプライト・別のシーンにも貼れます。
  定義ブロックの定義(ハット)を貼ると、IDの重複を避けて新しい定義として複製。足りない定義・変数は貼り付け先に補います。
- **スプライトへ複製**: ブロックをスプライト一覧のスプライトの上へドラッグして離すと、そのスプライトに複製(元のブロックは元の場所に残る)。
  元のスプライトだけのローカル変数は、相手側にもローカル変数として作ります。
  画面が狭くてスプライト一覧が見えないときは、ドラッグ中だけ画面上部にスプライトの帯が出ます。
- ドラッグ&ドロップ中に操作を取り消した(pointercancel)ときは、ブロックが消えず元の位置に戻ります。


## FPS(実行速度)を数値で変更
- アニメーションの実行ボタン(緑の旗・停止・リセット)の横の「FPS」欄に数値(1〜250)を入れて変更。Enterか欄の外をタップで確定。
- 実行中でも変えられ、すぐ反映。シーンごとに保存され、プロジェクトを開き直しても残ります(未設定は30)。
- sb3書き出しでは、30以外のとき TurboWarp の設定コメント(`_twconfig_`の`framerate`)としてステージに入れます。


## 実行中のブロック編集
- 実行中でも、ブロックの追加・移動・削除・入力値の変更・コピー&ペースト・バックパックが使えます(以前の「実行中は編集できません」を廃止)。
- 編集は約0.04秒後に、動いているオブジェクトとそのクローンへ反映されます(`liveApply`)。
  - すでに動いているスクリプトはそのまま続き、次に起動するとき(緑の旗・メッセージ・キー・クリックなど)から新しい内容になります。
  - 消したスクリプトは止まります。
  - 実行中に作った変数・リスト・定義ブロックは、すぐ使えます。
- 次の操作は、これまでどおり実行をリセットします: 変数・リストの名前変更や削除、オブジェクトの追加・削除・並び替え・位置などの変更、シーンの切り替え。


## ステージのコスチュームを背景に表示
- アニメーションのステージ背景に、ステージのコスチューム(コスチュームエディターで選んでいるもの)を貼り付けて表示します。背景色の設定は廃止(下地は白)。
- シーンにステージのオブジェクトがあるときは、そのオブジェクトが背景として描かれます(二重には描きません)。
- 「色に触れた」の判定にも背景が含まれます。
- 過去のプロジェクトに保存されている背景色の値は、読み込めますが使いません。
